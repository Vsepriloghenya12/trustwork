# Фриланс-платформа «TrustWork» (рабочее название)

Версия 1.0 · Статус: концепция утверждена, подготовка к MVP-разработке

## 1. Резюме проекта

TrustWork — платформа для фрилансеров нового поколения без платных откликов, с автоматической защитой оплаты (эскроу) и прозрачной системой доверия. Фрилансер гарантированно получает деньги за работу, заказчик — выполненную задачу без риска встретить скамера.

- **Формат продукта:** мобильное приложение для Android + мобильный сайт (PWA) для пользователей iPhone.
- **Бэкенд:** собственный сервер на Railway (Node.js + PostgreSQL).
- **Метод разработки:** AI-assisted development (код пишет Claude Code).

## 2. Проблема рынка

Действующие биржи (Upwork, FL.ru, Kwork) имеют системные болезни:

1. **Платные отклики** — фрилансер покупает «лотерейные билеты» без гарантии заказа.
2. **Скамеры** — «сделай бесплатное тестовое», «пришли исходники, потом заплачу», неоплата работы.
3. **Непрозрачность** — фейковые отзывы, накрученные портфолио, анонимные мошенники.
4. **Высокие комиссии** — 10–20% со сделки.
5. **Спам** — заказчики тонут в сотнях шаблонных откликов.

## 3. Концепция решения

Платформа переворачивает экономику биржи:

- **Подписки и подбор.** Фрилансер сохраняет поиск и получает push о новых подходящих проектах. Заказчик видит подходящих исполнителей прямо в карточке задачи и может пригласить их, не дожидаясь откликов.
- **Отклики бесплатны**, но их качество контролирует умный мэтчинг (фрилансер видит только релевантные проекты и осознанно «предлагает себя» коротким питчем — вместо веерного спама).
- **Эскроу — по выбору заказчика.** Публикация возможна и без заморозки бюджета, но комиссию заказчик платит в обоих случаях и вперед. Проекты с замороженным бюджетом получают бейдж «Оплата гарантирована» и приоритет в ленте. Фрилансер всегда видит до отклика, защищен ли бюджет.
- **Рейтинг заказчика.** Оценки оставляют только фрилансеры после реального диалога: отзыв текстом после диалога, звезды — после завершенной сделки. Фейковые отзывы отсекаются на входе.
- **Доверие строится не на паспорте**, а на деньгах под контролем платформы, «рабочем следе» и репутации.

## 5. Целевая аудитория

- **Фрилансеры** (дизайн, разработка, маркетинг, тексты, видео) — уставшие от платных откликов и кидалова.
- **Заказчики** — стартапы, малый бизнес, частные лица, которым нужны проверенные исполнители и защита предоплаты.
- **Ростовая фича (после MVP):** «Командные бандлы» — платформа собирает под задачу микро-команду (дизайнер + разработчик + копирайтер) с единым бюджетом и чатом.

## 6. Система доверия и анти-скам (5 уровней)

1. **Эскроу по выбору заказчика.** Двухстадийный платеж: холдирование → capture (выплата) или cancel (возврат). Заморозка дает бейдж «Оплата гарантирована» и приоритет в ленте; статус «Проверенный» фрилансеру засчитывают только сделки с эскроу.
1a. **Двусторонние рейтинги.** Оценить заказчика может только фрилансер, у которого был диалог с ним: после диалога — отзыв текстом (в рейтинг не идет), после завершенной сделки — полноценная оценка со звездами. Заказчик оценивает исполнителя звездами после завершения сделки. Накрутка бессмысленна: в рейтинг входят только оценки за сделки.
2. **Soft-KYC.** Верификация по SMS + бейджи за привязку «рабочего следа»: Telegram, GitHub, Behance.
3. **«Песочница» для новичков.** Аккаунты с 0 сделок помечены как «Новичок»: обязательный эскроу, лимиты. После 3 успешных сделок — статус «Проверенный».
4. **Закрытый контур.** Вся переписка и файлы — во внутреннем чате, контакты в сообщениях маскируются. Уводить сделку никто не запрещает и не банит за это: заказчик уже заплатил комиссию вперед, при эскроу деньги заперты на время работы, а рейтинг начисляется только за закрытые на платформе сделки.
5. **Арбитраж.** Спор решается поддержкой на основании внутренней переписки и ТЗ.

## 7. Пользовательские сценарии

**Фрилансер:** регистрация по телефону → выбор роли и навыков → умная лента проектов → «Предложить себя» (короткий питч) → чат с заказчиком → сдача работы → заказчик принимает → деньги автоматически разблокируются из эскроу.

**Заказчик:** регистрация по телефону → создание проекта → публикация (7%) или публикация с эскроу (5% сверх бюджета, бейдж «Оплата гарантирована» и приоритет в ленте) → выбор исполнителя из питчей → приемка работы → (при эскроу) деньги уходят исполнителю целиком.

## 8. Экраны и дизайн-система (по сгенерированным референсам)

- **Экран 1 — Лента проектов:** шапка с приветствием и уведомлениями; карточки с зеленым бейджем «Оплата в эскроу» (иконка замка), бюджетом и тегами; нижняя навигация: Лента / Поиск / Чаты / Профиль.
- **Экран 2 — Карточка проекта:** заказчик с галочкой верификации и рейтингом; зеленый блок «Безопасная сделка: сумма заморожена в эскроу»; чипы (срок, бюджет, теги); крупная кнопка «Предложить себя».
- **Экран 3 — Профиль фрилансера:** аватар, рейтинг, число отзывов; бейджи «Телефон подтвержден», «Telegram», «Проверенный фрилансер»; статистика; теги навыков; горизонтальное портфолио.
- **Экран 4 — Чат сделки:** баннер «Эскроу активен · сумма заморожена» с прогресс-баром; пузыри сообщений; карточка файла ТЗ; поле ввода.

**Дизайн-система:**

- Основной цвет — глубокий индиго/фиолетовый (`#3B3486` / `#5B4FE9`);
- Фон — белый/светло-серый, карточки с мягкими тенями и скруглениями;
- Акцент доверия — зеленый (эскроу, верификация);
- Стиль — финтех-минимализм, крупные кнопки.

## 9. Монетизация

Платит только заказчик. Исполнитель не платит ничего: ни за отклики, ни за поднятия, ни с полученных денег.

| | Публикация без эскроу | С эскроу |
|---|---|---|
| Ставка | **7%** от бюджета | **5%** сверх бюджета |
| Минимум | 300 ₽ | 300 ₽ |
| Потолок | 10 000 ₽ | нет |
| Когда списывается | при публикации, одним платежом | при публикации, одним платежом |
| Что получает исполнитель | платформа в расчетах не участвует | **100% бюджета** |

**Почему комиссия берется вперед.** Заказчик платит до первого отклика, поэтому увести сделку мимо платформы ему уже нечего: деньги уплачены. Это структурная защита вместо детекторов переписки и банов за обмен контактами.

**Возврат комиссии за публикацию:** если за 7 дней не пришло ни одного отклика либо заказчик отменил проект в первые 24 часа. Возврат уходит тем же путем, внутреннего баланса на платформе нет.

**Зачет при переходе на эскроу.** Уплаченные 7% засчитываются в счет 5%. Поскольку 7% всегда больше 5%, подключение эскроу после публикации выходит бесплатным, а разница не возвращается: выбрать эскроу сразу дешевле, чем передумать потом.

**При частичной выплате по спору** комиссия берется только с фактически выплаченной части.

Бесплатный период: пока подключается банк, комиссия равна нулю (`BILLING_ENABLED`), но тарифы в интерфейсе уже показаны — включение платы не должно стать сюрпризом.

Отложено до появления оборота: B2B-подписка заказчиков, фикс-fee за найм в штат, ускоренный вывод.

## 9а. Выплаты и статус исполнителя

Платформа перечисляет деньги **только самозанятым и ИП**. Выплата обычному физлицу сделала бы платформу налоговым агентом и потребовала бы страховых взносов сверх суммы сделки: на заказе в 30 000 ₽ это около 9 000 ₽ расхода против 1 500 ₽ комиссии.

- **Вне эскроу** статус исполнителя платформы не касается: заказчик рассчитывается напрямую.
- **Внутри эскроу** статус нужен в момент выплаты. Работать без него можно — откликаться, вести переписку, сдавать работу.
- Статус виден заказчику **до найма** — в отклике и в публичном профиле.
- После приемки на оформление дается **30 дней** (предел хранения денег на счете банка) с напоминаниями на 1, 7, 14 и 25 день.
- Не оформил — разбирает поддержка. Рычага два: продлить срок или закрыть с возвратом заказчику. Такая сделка не считается закрытой: звезды не получает никто, у исполнителя остается пометка, видная только поддержке.

## 9б. Закрытие сделки и споры

- **Приемка односторонняя:** заказчик принимает работу, деньги уходят исполнителю. Подтверждение исполнителя не требуется.
- **Отмена начатой работы — только с согласия исполнителя.** Заказчик предлагает отмену, исполнитель соглашается или отказывается; отказ открывает спор.
- **Спор** открывает любая сторона в любой момент сделки. Сначала 3 дня на то, чтобы договориться в чате, дальше решает поддержка на основании задания, файлов и переписки. Выплата может быть частичной.
- **Молчание исполнителя 14 дней** дает заказчику право закрыть проект самому — бюджет возвращается.

## 10. Техническая архитектура

- **Backend:** Node.js (NestJS/Express) + Prisma ORM + PostgreSQL → деплой на Railway.
- **Android:** React Native (Expo) или Flutter.
- **iOS:** PWA на Next.js (добавление на главный экран из Safari, без App Store).
- **Платежи:** Т-Банк Мультирасчеты — двухстадийные платежи (authorization → capture/cancel), выплаты и проверка статуса самозанятого по базе ФНС. Единственный способ оплаты — СБП: карточный эквайринг забирает 3,5–3,8% и делает нашу комиссию убыточной. Адаптер ЮKassa оставлен в коде как запасной вариант для приема платежей.
- **SMS-авторизация:** SMS.ru или Firebase Phone Auth.
- **Выплаты фрилансерам:** API-выплаты самозанятым с авточеками (входят в Мультирасчеты).
- **Фоновые сроки:** возврат комиссии, напоминания о статусе и передача споров поддержке двигаются почасовой проверкой (`services/maintenance.js`).

## 11. Модель данных (сущности Prisma)

- **User:** телефон (unique), роль (CLIENT/FREELANCER), рейтинг, статус для выплат (NONE / SELF_EMPLOYED / ENTREPRENEUR), привязки (Telegram/GitHub).
- **Project:** заголовок, описание, бюджет, уплаченная комиссия, вехи сделки (публикация, старт, приемка, срок оформления статуса). Статусы: DRAFT → PENDING_PAYMENT → OPEN (без эскроу) или FUNDED (с эскроу) → IN_PROGRESS → COMPLETED / AWAITING_PAYOUT / DISPUTED / CANCELLED.
- **Application:** отклик (питч), статусы PENDING / ACCEPTED / REJECTED.
- **Transaction:** движение денег, kind ESCROW (за работу) / FEE (комиссия), статусы PENDING / HOLDED / RELEASED / REFUNDED.
- **Dispute:** спор по сделке; статусы OPEN (стороны договариваются, 3 дня) / IN_SUPPORT / RESOLVED; хранит присужденную исполнителю сумму и решение.
- **Subscription:** сохраненный поиск фрилансера (направление, слово, минимальный бюджет, только с эскроу), до 10 штук; можно приглушить.
- **Notification:** событие в ленте уведомлений (новый проект по подписке, заморозка бюджета, приглашение, отклик, выбор исполнителя, приемка, ответ поддержки, решение по обжалованию, сообщение); один проект — одно уведомление.
- **PushDevice:** устройство, подписанное на push (web-push, ключи VAPID).
- **Invitation:** приглашение заказчика исполнителю; до 5 на проект, живет 14 дней и не дольше срока задачи; статусы SENT / VIEWED / ACCEPTED / DECLINED / EXPIRED.
- **Review:** двусторонняя оценка по проекту (subject — кого оценивают, author — кто); kind DIALOG (отзыв текстом после диалога) / DEAL (звезды после завершенной сделки, в обе стороны); рейтинг пользователя считается только по DEAL.

## 13. Процесс разработки (Claude Code)

- **Декомпозиция:** ИИ получает микро-задачи по шагам (БД → API → мобилка → веб), а не «сделай биржу целиком».
- В корне проекта — `PROJECT_SPEC.md` (этот документ) как постоянный контекст для ИИ.
- **Частые деплои:** GitHub → Railway автосборка.
- После критичной логики (эскроу) — запрос unit-тестов у ИИ.

## 14. Юридический блок

- **Форма:** ИП. Роль — **агент**: деньги заказчика платформе не принадлежат, она их проводит. Доходом ИП считается только комиссия, чек пробивается с признаком агента (тег 1057). Схема «платформа как исполнитель» отклонена: налог с оборота превысил бы выручку.
- На сайте — публичная оферта, пользовательское соглашение, политика обработки персональных данных и правила эскроу; открываются без входа (требование модерации RuStore).
- Деньги заказчиков лежат на счете банка и уходят исполнителю после приемки работы.
- **152-ФЗ:** нужно уведомление в Роскомнадзор до начала обработки данных и база, физически расположенная в России. Подробности и статус — в `LEGAL.md`.
- **Публикация в RuStore:** чек-лист — в `apps/android/RUSTORE.md`.
